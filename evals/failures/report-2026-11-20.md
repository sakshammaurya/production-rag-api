# RAG-005 failure-scenario report — 20 November 2026

This report separates natural retrieval observations from controlled generation stress tests. It
does not treat irrelevant retrieval as a failure unless correctness, faithfulness, abstention,
critical facts, latency, or token consumption is affected.

## Configuration

- API and database: local Docker Compose deployment from merge commit `859eeda`
- Isolation: dedicated `rag005` tenant in the existing local PostgreSQL/pgvector database
- Corpus: unchanged v2 synthetic corpus (two documents, seven pages)
- Embeddings: `nomic-embed-text`
- Generator: `qwen3:4b`, temperature `0`, Ollama OpenAI-compatible endpoint
- Retrieval: unchanged cosine search, `top_k=5`, similarity threshold `0.60`
- Provider and evaluation timeout: 600 seconds
- Natural report: `evals/failures/results/natural-2026-11-20.json`
- Controlled report: `evals/failures/results/controlled-2026-11-20.json`
- N1 retry: `evals/failures/results/n1-retry-2026-11-20.json`

The reports are committed as immutable evidence. The controlled report's deterministic C2 fact
label and C5 semantic-abstention label were rescored after the run using the current harness; saved
answers, provider token counts, and timings were not regenerated.

The first ingestion attempt exposed a stale pre-tenant API image and failed transactionally with no
`rag005` rows. The API image was rebuilt from `main`; PostgreSQL was preserved, and the verified

## Experiment A — natural retrieval

### N1 — manager-approved Wednesday exception

- Initial request: generation timed out at 600.007 seconds; the API logged a provider read timeout.
- One warm retry: HTTP 200 after 488.553 seconds.
- Retrieval on retry:
  1. Employee Handbook page 1, similarity `0.8141` (relevant).
  2. Employee Handbook page 2, similarity `0.6012` (irrelevant expense-policy noise).
- Answer: `Yes, [Source 262, Page 1]`.
- Machine-readable retry evidence: `results/n1-retry-2026-11-20.json`.

The relevant page ranked first, so no retrieval failure was demonstrated. The answer is defensible
because the question already states manager approval, but it does not restate the Wednesday rule or
exception. Classification: **generation reliability failure and answer-completeness near miss**.
The repeated 488–600 second latency is query-specific and far above the historical baseline.

### N2 — $600 expense deadline and approval

- Latency: 121.318 seconds.
- Retrieval: Employee Handbook page 2 ranked first, similarity `0.7655`; no other source passed the
  threshold.
- Answer included the 10-calendar-day deadline, manager approval, and the above-$500 condition.
- Expected facts, evidence coverage, citation, and abstention behavior all passed.

Classification: **no failure observed**.

### N3 — security reporting and handling

- Latency: 81.032 seconds.
- Retrieval: page 3 ranked first (`0.7823`), page 4 ranked second (`0.7010`).
- Answer said to report within one hour, not investigate, preserve evidence, and wait for security
  instructions.
- Critical-fact recall, expected facts, evidence coverage, and both citations passed.

Classification: **no failure observed**.

### N4 — commuter stipend versus parking

- Latency: 88.050 seconds.
- Retrieval: Benefits FAQ page 1 ranked first (`0.7611`); unrelated home-office page 2 ranked second
  (`0.6347`).
- Answer correctly limited the $75 benefit to eligible public-transit costs and said parking was not
  supported by the evidence.

Classification: **harmless retrieval noise**. The unrelated passage did not change correctness,
faithfulness, or citation selection.

### N5 — unsupported parking price

- Latency: 0.390 seconds.
- No chunk passed the `0.60` threshold; generation was skipped.
- The API returned its standard insufficient-evidence answer, `abstained=true`, and no sources.

Classification: **no failure observed; correct abstention**.

### Natural-test conclusion

The original five-case report's aggregate retrieval, answer, and citation rates are `0.75` because
N1's timed-out request is recorded as a failed case with no response. That aggregate must not be
misread as a 25% retrieval-error rate. All four completed initial requests behaved correctly, and
N1's retry retrieved the correct page first. The demonstrated natural failure is highly variable,
sometimes timeout-level generation latency—not retrieval quality.

## Experiment B — controlled context perturbation

Controlled passages were passed directly to the existing production prompt and generator. They were
never embedded or inserted into PostgreSQL. Token counts are provider-reported totals and include
the model's reasoning tokens, not only visible answer text.

|---|---:|---:|---:|---|
| C1 commuter + home-office distractor | 63.945s → 63.105s | 140 → 185 | 301 → 299 | Correct in both; harmless noise |
| C2 home office + commuter distractor | 69.567s → 55.715s | 142 → 187 | 326 → 255 | Correct in both; perturbed answer added valid detail |
| C3 PTO + two benefit distractors | 57.958s → 65.403s | 143 → 233 | 273 → 308 | Correct in both; small measured overhead |
| C4 security + fabricated contradiction | 114.719s → 105.615s | 171 → 192 | 499 → 473 | Safe answer in both; conflict rejected |
| C5 no parking evidence + commuter near-miss | 0s → 74.428s | 0 → 141 | 0 → 329 | No price invented; semantic abstention preserved |

### Controlled observations

- C1: both variants returned the $75 monthly public-transit stipend and cited only the commuter
  source.
- C2: both returned $100. The perturbed answer also correctly stated that it is one-time and
  available after 90 days; it did not confuse the $75 stipend with the allowance.
- C3: both returned 15 days and cited only the PTO source. Added evidence increased prompt tokens by
  90, completion tokens by 35, and latency by 7.445 seconds in this single run.
- C4: the perturbed answer explicitly retained “must not investigate,” the one-hour deadline,
  evidence preservation, and security-team instructions. It cited only the two real policy pages,
  not the fabricated conflicting source.
- C5: the perturbed generator stated that the evidence contained no parking-price information and
  did not turn the $75 stipend into a parking price.

Classification: **no controlled reliability failure observed**. C1–C3 demonstrate harmless noise;
C3 shows a small single-run efficiency cost. C4 passed the adversarial contradiction test. C5
preserved a semantic abstention, although the production API currently sets `abstained=false`
whenever any evidence reaches generation. That API flag behavior is a potential contract issue if a
future near-miss passage crosses the retrieval threshold, even when the generated text abstains.

## Limitations

- Five natural and five paired synthetic cases are probes, not general reliability estimates.
- Each controlled variant ran once. Temperature zero does not guarantee deterministic runtime or
  output, and latency variance is large enough that small differences are not causal evidence.
- Controlled generation bypasses retrieval by design and therefore cannot prove that production
  retrieval would naturally supply the injected context.
- The automated lexical checks are narrow; the classifications above also inspect the raw answers
  and exact evidence.
- The natural API does not expose generation token usage. Controlled token counts were captured
  directly from the provider response.
- The controlled harness detects semantic abstention from text. The production response's
  `abstained` field instead reflects whether retrieval returned evidence.

## Evidence-based recommendations

1. Leave retrieval configuration unchanged. No natural wrong-page or missed-page failure was
   demonstrated.
2. Investigate N1's extreme generation latency separately. Add a bounded generation policy or use
   an explicitly selected non-thinking generation mode only as a new measured experiment; do not
   conflate that work with retrieval tuning.
3. Clarify the API abstention contract so a model-generated insufficient-evidence answer cannot be
   returned with `abstained=false` merely because a near-miss chunk passed retrieval.
4. Repeat the controlled pairs before making efficiency changes. Only C3 showed higher latency and
   token use, and one run is insufficient for tuning.
5. Add harder contradiction and near-miss cases only after preserving this baseline unchanged.
